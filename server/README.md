# Подписка WhySlow: инструкция для владельца

Платные функции лежат в открытом коде, но открываются только ключом. Ключ — это документ,
подписанный вашим **закрытым ключом**. В программе лежит только **открытый** ключ: им можно
проверить подпись, но нельзя сделать новую. Поэтому, прочитав код, ключ не подделать.

Есть два способа продавать подписку. Начните с первого (ничего не нужно разворачивать),
второй подключите, когда захотите выдавать ключи через бота и оплату в Telegram.

| | Ключ для устройства (без сервера) | Код активации (с сервером) |
|---|---|---|
| Как выглядит | `WS1.eyJ...` (длинная строка) | `WS-K7Q2-M9XW-PA3B-CDEF` |
| Что делает покупатель | присылает «Код этого компьютера» из окна «Подписка» | просто вводит код |
| Перенос на другой ПК | вы выпускаете новый ключ | сам: «Отключить на этом компьютере» и ввести на новом |
| Отзыв | нельзя, работает до конца срока | `revoke`, перестаёт работать в течение суток |
| «Все устройства» | перечисляете коды всех устройств | до 10 устройств, подключаются сами |
| Нужен интернет | нет | раз в неделю |

## 1. Один раз: создать ключи

```bash
python owner/keys.py init
```

* В `~/.whyslow-owner/private.key` появится **закрытый ключ**. Сделайте резервную копию
  (флешка, менеджер паролей) и никому не показывайте. Потеряете — придётся выпустить новую
  версию программы, а все старые ключи перестанут работать. Утечёт — любой сможет делать ключи.
* Открытый ключ впишется в `whyslow/license.py` (`PUBLIC_KEY = "..."`). Его закоммитьте
  и выпустите новую версию: только после этого программа начнёт принимать ключи.

## 1a. Как защищён код платных функций

Код каждой платной функции лежит в `whyslow/premium/<функция>.py`, но в готовую программу он
попадает **зашифрованным** (`<функция>.wsl`). Расшифровать его можно только ключом функции, а
ключ выводится из вашего закрытого ключа и приходит внутри ключа подписки — то есть лишь после
оплаты. Поэтому вырезать проверку подписки из открытого кода бесполезно: без ключа расшифровать
и запустить функцию нечем.

Вам для этого ничего делать не нужно: сборка (`python packaging/build.py`) сама шифрует модули,
если видит ваш закрытый ключ (файл `~/.whyslow-owner/private.key` или переменная
`WHYSLOW_SEAL_SEED` с тем же hex — удобно в CI). Если ключа при сборке нет, она предупредит, что
функции пойдут открытым кодом, — так собирайте только для себя, не для раздачи.

Проверить вручную: `python owner/seal.py --list` (что зашифровано), `python owner/seal.py`
(зашифровать), `python owner/seal.py --clean` (вернуть для разработки).

Честная граница: тот, кто **оплатил** подписку, получает ключи и в принципе может достать
расшифрованный код. От этого не защищён никто. Шифрование закрывает доступ тем, кто не платил, и
обесценивает правку проверки в коде; а функции, которые считаются на сервере (например, сравнение
с похожими ПК), без действующей подписки не работают вовсе.

## 2. Продажа без сервера

1. Покупатель открывает WhySlow → «★ Подписка» внизу окна и присылает вам «Код этого компьютера»
   (например, `K7Q2M-9XWPA`) и оплату (перевод, СБП — как вам удобно).
2. Вы выпускаете ключ:
   ```bash
   python owner/keys.py issue solo 1 K7Q2M-9XWPA --note "Иван, @ivan"
   python owner/keys.py issue family 1 K7Q2M-9XWPA, ABCDE-FGHIJ, ...
   ```
   (тариф, сколько месяцев, коды устройств). Выданные ключи записываются в `~/.whyslow-owner/issued.jsonl`.
3. Отправляете строку `WS1....` покупателю, он вставляет её в поле «Ключ» → «Активировать».

## 3. Сервер активации (Cloudflare Workers, бесплатно)

Сервер хранит коды, считает устройства, позволяет отзывать и продлевать коды, и в нём же живёт
Telegram-бот. Бесплатного тарифа Cloudflare (100 000 запросов в день) хватит с большим запасом.

1. Зарегистрируйтесь на <https://dash.cloudflare.com> и установите Node.js 20+.
2. В папке `server`:
   ```bash
   cd server
   npm install
   npx wrangler login
   npx wrangler kv namespace create LICENSES
   ```
   Последняя команда напечатает `id = "..."` — впишите его в `wrangler.toml` вместо `REPLACE_WITH_KV_ID`.
3. В `wrangler.toml` впишите `PUBLIC_KEY` — тот же, что в `whyslow/license.py`.
4. Секреты (каждая команда спросит значение):
   ```bash
   python ../owner/keys.py server-secret        # скопируйте вывод
   npx wrangler secret put PRIVATE_KEY          # и вставьте сюда
   npx wrangler secret put ADMIN_TOKEN          # придумайте длинный пароль (40+ случайных символов)
   ```
5. `npx wrangler deploy` — напечатает адрес вида `https://whyslow-license.<ваше-имя>.workers.dev`.
   Откройте его в браузере: должно быть `{"ok":true,...}`.
6. Адрес впишите в `whyslow/license.py` (`SERVER_URL = "https://..."`) и выпустите новую версию.
7. Для `owner/keys.py` создайте `~/.whyslow-owner/server.json`:
   ```json
   {"url": "https://whyslow-license.<ваше-имя>.workers.dev", "admin_token": "тот же пароль, что ADMIN_TOKEN"}
   ```

Теперь коды выпускаются так:

```bash
python owner/keys.py code solo 1 "Иван, @ivan"     # → WS-XXXX-XXXX-XXXX-XXXX, отправьте покупателю
python owner/keys.py code family 12 "Пётр, год"
python owner/keys.py extend WS-XXXX-... 1          # продлить на месяц (после следующей оплаты)
python owner/keys.py revoke WS-XXXX-...            # отозвать
python owner/keys.py unlink WS-XXXX-... K7Q2M-9XWPA  # освободить место, если человек сменил ПК
python owner/keys.py list
```

Сам код в базе не хранится, только его хеш, поэтому `list` показывает коды по короткому id
(его тоже можно передавать в `extend` и `revoke`). Сохраняйте выданные коды у себя, если они понадобятся.

## 4. Telegram-бот (по желанию)

1. В Telegram у [@BotFather](https://t.me/BotFather): `/newbot` → получите токен.
2. Узнайте свой числовой id у [@userinfobot](https://t.me/userinfobot) и впишите его в `wrangler.toml`
   (`OWNER_CHAT_ID`), а в `OWNER_CONTACT` — как вам писать покупателям (например, `@ваш_ник`).
3. Секреты и запуск:
   ```bash
   npx wrangler secret put TG_TOKEN     # токен от BotFather
   npx wrangler secret put TG_SECRET    # любая случайная строка из букв и цифр
   npx wrangler deploy
   ```
4. Подключите бота к серверу (одна команда, подставьте свои значения):
   ```bash
   curl "https://api.telegram.org/bot<TG_TOKEN>/setWebhook" \
     -d url="https://whyslow-license.<ваше-имя>.workers.dev/tg/<TG_SECRET>" \
     -d secret_token="<TG_SECRET>"
   ```

Что умеет бот:

* **Вам** (команды работают только из вашего аккаунта): `/solo 1 Иван` — новый код «Соло» на месяц,
  `/family 12 заметка`, `/extend КОД 1`, `/revoke КОД`, `/unlink КОД XXXXX-XXXXX`, `/info КОД`, `/list`.
  Код приходит отдельным сообщением — его удобно переслать покупателю.
* **Покупателям**: тарифы и как с вами связаться.

### Оплата прямо в боте

Если подключить платёжного провайдера, покупатель платит в боте и сразу получает код, а вам
приходит уведомление. В @BotFather: ваш бот → Payments → выберите провайдера (например, ЮKassa),
пройдите его подключение и получите токен, затем:

```bash
npx wrangler secret put PAYMENT_TOKEN
npx wrangler deploy
```

Появятся команды `/buy_solo` и `/buy_family`. Код выдаётся один раз на платёж и только если
сумма совпала с ценой тарифа. Продление по оплате — та же покупка: человек получает новый код.

## Насколько это надёжно

* **Подделать ключ нельзя**: нужна подпись закрытым ключом, а он есть только у вас и на сервере.
  Подменить ответ сервера тоже нельзя: программа проверяет подпись и у ключей, пришедших с сервера.
* **Поделиться ключом не выйдет**: ключ привязан к коду компьютера; код активации подключается
  к ограниченному числу устройств, и сервер это считает.
* **Переведённые назад часы** программа замечает и не открывает функции.
* **Вырезать проверку бесполезно**: код платных функций в сборке зашифрован (см. раздел 1a),
  ключ даёт только оплаченная подписка. Без ключа расшифровать и запустить функцию нечем.
* **Честно о границах**: тот, кто оплатил, получает ключи и в принципе может достать расшифрованный
  код функции. Полностью это не закрывается ни в одной программе, которая работает у пользователя.
  Защищает от такого только то, что выполняется на сервере (например, сравнение с похожими ПК):
  без действующей подписки сервер такие запросы не обслуживает.

## Для разработчиков платных функций

Код функции — отдельный модуль `whyslow/premium/<функция>.py` с функцией `build(main) -> QWidget`
(в релизе он шифруется автоматически). Во вкладки он подключается через замок:

```python
from whyslow.license_ui import PremiumGate
tabs.addTab(PremiumGate("compare", main=main), "Сравнение")   # грузит whyslow/premium/compare.py
```

`PremiumGate` сам показывает замок без подписки и строит вкладку, когда ключ функции получен.
Остальной API:

```python
from whyslow import license
license.has_premium("compare")        # True, если подписка действует (для своих проверок)
license.on_change(callback)           # включили, отключили, закончился срок
license.auth_headers()                # заголовок для запросов к серверу

from whyslow import premium
tab = premium.widget("compare", main) # вручную; PremiumLocked, если подписки/ключа нет
```

На сервере: `const a = await requireLicense(request, env); if (!a.ok) return a.response;`
(`src/auth.js`), обработчик подключается строкой в `ROUTES` в `src/index.js`.

Тесты: `python -m pytest tests` и `cd server && npm test`.
